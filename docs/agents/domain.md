# Domain Docs

This repo has a single domain context.

## Before exploring, read these

- `CONTEXT.md` at the repo root for the project glossary.
- `docs/adr/` for architectural decisions relevant to the work.
- Product and technical docs under `docs/` for feature requirements and implementation context.

## Use the glossary's vocabulary

When output names a domain concept, use the term as defined in `CONTEXT.md`. Do not drift to synonyms the glossary explicitly avoids.

## Flag ADR conflicts

If a proposal contradicts an existing ADR, surface it explicitly rather than silently overriding it.
